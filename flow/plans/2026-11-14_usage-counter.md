# Plan — cmd-pallet usage counter

**Worktree:** /data/worktrees/cmd-pallet-wt--wt-usage-counter · **Branch:** wt/usage-counter · **Base:** main@8d21990
All Tasks run in the pinned worktree (`git -C /data/worktrees/cmd-pallet-wt--wt-usage-counter rev-parse --show-toplevel`). Intentions: `flow/intentions/2026-11-14_usage-counter.md` ([U1]..[U6]).

**Goal:** every cmd-pallet invocation bumps a counter in a JSON file inside this repo, and the counts get committed and pushed so all machines' usage merges in git; a `stats` verb reads the merged files. [U1][U2][U5][U6]
**Architecture:** `src/usage.ts` (pure store: key, increment, lock, atomic write) + `src/usage-lock.ts` (one owned lock for store + sync) + `src/usage-sync.ts` (debounced detached git commit/push of `usage/` only) + `src/usage-stats.ts` (pure read/aggregate). `runCli` wraps `dispatch`: after the verb finishes, record usage; any usage error is swallowed (never changes exit code or output). [U1][U2][U6]
**Tech:** Node ≥22.18 strip-types TS, `node:*` only, vitest. [U1 "inside the cmd-pallet repository itself"]

## Data contract [U3][U4]
- `usage/<hostname>.json` → `{ "<hostname>": { "<action>": { "YYYY-MM-DDTHH": n } } }` [U3]
- `usage/<hostname>.cmds.json` → `{ "<hostname>": { "<cmd>": { "<action>": { "YYYY-MM-DDTHH": n } } } }` — only `read`, `get`, `run` (verbs that take one cmd); `<cmd>` = `<agent>:<name>` of the resolved command (same `agent:name` form the CLI already prints for ambiguous candidates), else the name as typed (not found / ambiguous). Two agents' same-named cmds stay separate rows. Keys recorded before r5 (bare name) are left as-is and show as their own rows (no migration). [U4 "put what cmd being read"][TL-1]
- date-hour = UTC. hostname = `os.hostname()` (the `<hostname>` key of [U3]). action per intention elaboration of [U2]. [U3][U5 "between multiple machine" → one clock]
- One file per host → two machines with distinct hostnames never edit the same file → git merge never touches the same file. [U5 "merged usage between multiple machine utilizing git"]
- Same-hostname machines (two machines whose `os.hostname()` is equal) [G5]. Resolution [U3][U6]: the user keyed the machine by `<hostname>` ([U3] "{ <hostname>: ...", [U6] "which machine") → in the user's own data model one hostname = one machine; distinct hostnames are a stated precondition (README, Task 4), not a defect to engineer around. Fail-safe when the precondition is broken (fix step + test, Task 3 step 4 + RED "same host file on two clones"): the worker aborts only its own merge and stops; no count is lost (local file + local usage commit kept), nothing half-merged is pushed, CLI output/exit unchanged; the stuck push is fixed by hand after renaming a host. Automatic merge of a shared host file (sum merge driver, host override) is NOT built: no [U#] asks for it; @A cap decision B ([[2026-11-14_spb-gate-cap]]) parked it as bead cpal-qp8.10. ## Task 1 — usage store [U1][U3][U4]
Files: create `src/usage.ts`, `tests/usage.test.ts`.
- `dateHourKey(d: Date): string` → UTC `YYYY-MM-DDTHH`. [U3 "date-hour"]
- `actionOf(verb, flags, known)` → action string per [U2] elaboration (`--help`/no verb → `help`, `--version` → `version`, unknown verb → `unknown`). [U2 "any action"]
- `src/usage-lock.ts`: `acquireOwnedLock(lock, {retries, retryMs, staleMs}) → nonce | undefined` / `releaseOwnedLock(lock, nonce)` — ONE helper, used by the store lock (`<dir>/.lock`) AND the sync lock (`usage/.sync-lock`, Task 3). Lock = atomic `mkdir` + `owner` file `{pid, start, ns, nonce}`: `start` = `<boot_id>:<starttime>` from `/proc`, `ns` = `/proc/self/ns/pid`. Owner in OUR pid namespace → broken ONLY when provably gone: `kill(pid,0)` → `ESRCH`, or state `Z` (zombie), or pid alive with a different `start` (pid reused) [G12]; never by age. Owner unknown / other namespace / no `/proc` identity → age rule (`staleMs`). Breaking is serialized [G13]: a breaker first takes `<lock>.break` (atomic `mkdir`; EEXIST → no break this attempt, wait `retryMs` and retry; `.break` itself older than `staleMs` → removed, a breaker holds it for microseconds), then RE-EVALUATES `isStale` on a fresh `readOwner` and removes only if still stale AND the nonce equals the one first seen, then removes `.break`. A lock acquired after the first look is fresh with a live owner → never stale → never removed; two breakers can no longer both act on one old nonce. Test seam: optional `beforeBreak?: () => void` in the options, called after the recheck, right before removal (tests only). Release removes only its own nonce. [U2 every invocation counts → no lost increment][U1][G6][G12][G13] (same-class defect in both locks → fixed once)
- `recordUsage({dir, host, action, cmd?, now})`: `acquireOwnedLock(<dir>/.lock, retries 50 × 20 ms)` — busy with live owner after budget → give up silently (never slows the CLI), read JSON (missing/corrupt → `{}`; corrupt file renamed `*.corrupt-<ts>`), increment, write sorted JSON to tmp + `rename`. [U3 "keep increase it"][U1]
- Store objects are null-prototype and walked by own keys only → a cmd/host named `__proto__`/`constructor` is stored as a plain key, never pollutes prototypes. [U4 "put what cmd being read" — cmd name is user input]
- RED first: key format; first increment; repeated increment same hour; new hour new key; cmds file only when `cmd` given; 20 parallel `recordUsage` calls → count 20; corrupt file recovery; `__proto__` cmd name stored as key [U3][U4]; owned lock [G6][G12]: live owner (pid + matching start identity) with mtime 11 s old → NOT broken, second `recordUsage` records after the holder releases → count 2; owner pid exited → broken immediately, count 1; owner pid reused (live pid, other start identity) → broken, count kept, no hang [G12]; zombie owner → broken; owner in another pid namespace → kept while fresh, broken once aged; ownerless lock dir aged → broken, fresh → kept. [U2][G6][G12]; breaker race [G13]: stale lock (dead-pid owner N0); breaker B2 = `acquireOwnedLock(lock, {retries 1, beforeBreak: () => { b1 = acquireOwnedLock(lock, {retries 1}) }})` → at most ONE of `b1`/B2's result is a nonce, and the lock's `owner` nonce equals that one (fails today: B1 breaks + acquires, then B2 removes B1's lock and acquires too → two holders); `.break` left by a dead breaker, aged → removed and the stale lock still breaks; fresh `.break` → no break, no hang (gives up after retries). [U2][G13]
