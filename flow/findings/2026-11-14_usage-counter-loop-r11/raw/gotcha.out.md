OPEN_RANK3PLUS=11 [rename(2)](https://man7.org/linux/man-pages/man2/rename.2.html) documents that renaming a directory over an existing directory is permitted only when the target is empty; a non-empty target returns `ENOTEMPTY` or `EEXIST`. Since the private temp and lock paths are siblings, they reside on the same mounted filesystem, so the plan’s basic rename claim is sound for that layout. The unresolved issue is the concurrent temp cleanup/rename behavior, which the plan does not specify or test.
